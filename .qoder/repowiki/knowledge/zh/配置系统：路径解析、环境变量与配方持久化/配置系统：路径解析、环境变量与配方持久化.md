## 1. 采用的方案

仓库没有引入外部配置框架（无 `config/`、`*.yaml`、`*.toml`、`.env` 文件），而是采用 **Python 标准库 + 环境变量** 的轻量配置方式，集中在以下位置：

- 应用运行路径与构建信息：`app_paths.py`
- 统一版本号：`app_version.py`
- 日志初始化与全局异常兜底：`logging_setup.py`
- GitHub 更新检查（含版本比较）：`update_check.py`
- 示教/参数型配方 JSON 的加载、校验、持久化：`recipe.py`
- 启动入口装配顺序：`main.py`

## 2. 关键文件与职责

| 文件 | 配置职责 |
|---|---|
| `app_paths.py` | PyInstaller onefile / 源码两种模式下的资源路径、用户数据目录 (`LOCALAPPDATA/Aurascope`)、日志目录、构建日期 |
| `logging_setup.py` | 滚动日志 (`RotatingFileHandler`, 1MB × 5)、主线程与工作线程未捕获异常兜底、错误对话框（复制详情/打开日志） |
| `app_version.py` | 单一常量 `APP_VERSION = '6.3.0'`，被窗口标题与更新检查共用 |
| `update_check.py` | 调用 GitHub Releases API，使用 `packaging.version.Version` 比较；失败静默忽略，仅对 `manual=True` 时发出 `check_finished` 信号 |
| `recipe.py` | 配方根目录解析、v1 参数型与 v2 示教型配方的读写、字段校验与默认值填充、schema 版本兼容 |
| `main.py` | 启动装配顺序：先 `setup_logging()` → `install_excepthook()` → 设置 Qt HighDPI/Fusion 样式 → 创建 `MainWindow` |

## 3. 架构与约定

### 3.1 路径解析策略（PyInstaller 兼容）

`app_paths.resource_path(name)` 通过 `sys._MEIPASS` 判断 onefile 打包模式，回退到源码目录；`app_dir()` 通过 `sys.frozen` 区分 exe 与源码。`local_data_dir()` 优先取 `LOCALAPPDATA` 环境变量，否则展开 `~\AppData\Local`，并自动 `makedirs`。

### 3.2 环境变量清单

| 变量 | 来源 | 作用 | 默认行为 |
|---|---|---|---|
| `QT_QPA_PLATFORM=windows` | `main.py` 硬编码 | 强制 Qt 平台为 Windows（测试中用 `offscreen` 覆盖） | 桌面端固定 windows |
| `QT_QPA_PLATFORM=offscreen` | 测试脚本 (`test_*.py`) | 在无 GUI 环境运行 UI 测试 | 跳过需要真实窗口的交互 |
| `AURASCOPE_RECIPE_DIR` | `recipe.py` + 测试 | 覆盖配方存储根目录 | 打包后 `exe/recipes`，不可写回退到 `local_data_dir()/recipes` |
| `AURASCOPE_AUTO_CONFIRM=1` | `ui_components.py` | 跳过确认对话框（自动化/测试） | 正常流程显示确认框 |

### 3.3 日志配置

`logging_setup.setup_logging()` 安装一个带 `_aurascope` 标记的 `RotatingFileHandler`，单文件 1MB、最多 5 个备份，格式为 `%(asctime)s %(levelname)s [%(name)s] %(message)s`，写入 `<local_data_dir>/logs/aurascope.log`。`install_excepthook()` 同时 hook `sys.excepthook` 与 `threading.excepthook`，将未捕获异常以 `critical` 级别写入日志并弹出 `QMessageBox`（无 GUI 时静默）。

### 3.4 更新检查降级

`update_check.UpdateChecker.check()` 网络请求超时 8s，失败仅记录 warning 日志；仅当 `manual=True` 时才通过 `check_finished` 信号把错误文案传给 UI。`parse_latest_release()` 直接丢弃 `draft` 与 `prerelease` 发布；`release_is_newer()` 对无法解析的版本号视为“不新”。

### 3.5 配方配置（JSON）

`recipe.py` 是仓库内唯一的结构化配置文件载体。核心约定：

- 根目录由 `_recipe_root()` 决定：优先 `AURASCOPE_RECIPE_DIR`；否则 exe 同级的 `recipes/`，不可写时回退到 `local_data_dir()/recipes/`。
- 文件名规则：参数型 `.json`，示教型 `.taught.json`，二者命名空间隔离（见 `_taught_path_for` 注释）。
- schema 版本：`build_recipe` 写入 `schema_version`；`normalize_recipe` 根据 `type == 'taught'` 走 v2 校验，其余按 v1 处理。
- 字段校验：`validate_detection` 合并 `DETECTION_DEFAULTS`，布尔/浮点/整型分别夹紧到 `_RANGES`；`validate_roi` 清洗多边形顶点、限制层阈值 0–255、顶点数 3–120。
- 读取容错：`list_recipes` 对损坏 JSON 按 v1 处理，让用户能在界面上看到并删除。

## 4. 约定与约束

- **路径解析必须经 `app_paths`**：`resource_path`、`app_dir`、`local_data_dir`、`log_dir` 是访问运行时路径的唯一入口，避免在业务模块里直接拼接 `sys.executable` 或 `__file__`。
- **日志必须先于 QApplication 初始化**：`main.py` 中 `setup_logging()` 和 `install_excepthook()` 在创建 `QApplication` 之前调用，确保 Qt 内部异常也能落盘。
- **Qt 平台由环境变量控制**：`main.py` 强制 `QT_QPA_PLATFORM=windows`；测试通过 `os.environ.setdefault('QT_QPA_PLATFORM', 'offscreen')` 覆盖，用于无头 UI 测试。
- **配方目录可被 `AURASCOPE_RECIPE_DIR` 完全覆盖**：该变量优先级最高，测试广泛使用它指向临时目录。
- **更新检查失败不阻断启动**：`update_check` 的网络异常只记日志，UI 仅在手动触发时收到错误信号，属于显式降级设计。
- **版本号唯一来源**：`app_version.APP_VERSION` 是窗口标题与更新检查的共同来源，禁止在别处硬编码版本号字符串。
- **无外部配置框架**：仓库不使用 `pydantic-settings`、`dynaconf`、`toml`、`yaml` 等第三方配置库；所有配置均通过 Python 常量、环境变量与 JSON 文件完成。
