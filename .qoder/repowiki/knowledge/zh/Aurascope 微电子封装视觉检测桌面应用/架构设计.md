仓库根以 main.py 为唯一启动点，由 app_entry_and_core 完成路径、版本、日志与更新检查装配，再实例化 main_window_shell（main_window.py）作为 Tab 容器；业务页面（tab_panels）通过 ui_components_and_dialogs 的 create_* 工厂与 QSS token 构建控件，并调用 algorithm_layer（image.py）执行空洞检测、距离测量、剪切力计算等算法，结果经 canvas_layers 的坐标转换与撤销栈刷新到对应画布；teaching_workflow 将算法产出的模型持久化为 recipe JSON，供各 Tab 复用；recipes_and_docs 集中存放已标定示教样本、PyInstaller spec 与用户文档；tests 针对 image.detect_defects、area_tab UI 与 update_check 做 unittest 覆盖。

跨子模块的关键契约：
- 数据流单向：Tab → image.py 算法 → Canvas 绘制 → CSV/图片导出，Tab 不直接操作图像像素。
- 路径与资源统一由 app_paths.py 解析，支持源码运行与 PyInstaller onedir 打包两种模式。
- 所有 Qt 交互通过 ui_components.py 的工厂函数创建，避免在 Tab 中散落布局代码。
- 配方 JSON 由 recipe.py 读写，字段语义与版本兼容策略被 teaching_workflow 与各业务 Tab 共同遵守。
- 打包产物遵循 AurascopeV6.spec 约定：on dir 输出 dist/AurascopeV6.3/，Splash 使用 splash_boot.png，version_info.txt 注入 Windows 文件属性。
