## 修正：金锡「拼接图」（拼接tab）无缝 + 对齐 + 深灰背景（14:11 起）

**先认错**：上一条我把用户说的"拼接图"理解成了**空洞率汇总拼图** ✗，
去改了 `render_summary_sheet`/ReportGo 的汇总图 ✗ —— 用户实际说的是**金锡拼接（Stitching tab）导出** ✗。
（汇总图那两处改动是**可选参数**，默认行为不变 ✔，随时可回退 ✔）

### 真正的根因（`stitching_canvas.py::stitch_images` 旧实现）
只用了标记点的 **Y 坐标**：`shift = end_ys[i] - start_ys[i+1]` ✗，
**X 坐标被完全忽略** ✗ → 每张图按**整幅宽度**硬接（`x_offset += w` ✗）
→ 重叠区被重复/内容错位 ✗ → **既不齐也有缝** ✗✗（正是用户反馈的现象）

### 修复（重写 `stitch_images`）
1. **X/Y 双轴对齐**：第 i 张"尾点"与第 i+1 张"头点"是同一处特征 →
   原点偏移由两点 **dx 与 dy 同时决定** → 重叠区自动正确 ✔
2. **羽化融合（真无缝）**：按权重累加 `acc += img*w; wsum += w` 再归一化，
   重叠区线性过渡 → 接缝不可见 ✔
   **关键**：只在**有重叠的那一侧**羽化 ✗ —— 否则整条图最外缘会"淡出"到背景（暗边 ✗）
3. **深灰背景**：未覆盖区域 = `STITCH_BG = 64`（模块顶部常量，改一行即可）✔
4. 去掉了原来 `+10` 的边距和多算的高度 ✔（画布按实际覆盖范围精确计算 ✔）

### 严格测试 `test_stitching.py`（新增，PASS=8）
拿**一张真实图**裁成两张有已知 120px 重叠的瓦片 → 在同一特征上打标记 → 拼回来：
- 输出尺寸 = 原图 **768×887** 完全一致 ✔
- **缝带平均差 0.12/255**、**全图平均差 0.02/255** → 真正无缝+对齐 ✔
- 标记打偏 10px → 输出严格跟随标记（±2px）✔
- 未覆盖区域像素 **恰好 64**（深灰）✔
- 对比图 `.workbuddy/validation/stitch_compare.png`（原图/旧硬接/新羽化）

### 一个诚实的失败记录
试过"互相关自动微调"（`_refine_by_overlap`，±24px 搜索平均绝对差）：
- 第一版 sentinel 写成 `0.0` 而得分是负数 → **永远不接受修正** ✗（被测试抓到 ✔）
- 改对之后：它把**已经完美对齐**的结果反而改坏 ✗（768px → 786px ✗）
→ **默认关闭**（`STITCH_AUTO_REFINE = False`），并把实测原因写进注释 ✔
   结论：标记对齐本身已足够准，自动微调在这类窄条纹理上不可靠 ✗
